# Step 5: PR 본문 작성

WRITING 세션의 유일한 스텝. IMPL 세션(step-3·4)까지 마친 브랜치에서 PR 본문을 작성하고, `/plan/pr{N}/` 산출물을 정리한다.

## 준비

PR 본문은 qube 레포 `.github/PULL_REQUEST_TEMPLATE.md`의 4절 구조를 그대로 채운다:

```
[Jira 링크](링크추가해주세요)

### 작업 배경

### 변경 사항

### 집중적으로 봐줬으면 하는 것
```

멀티 PR이면 앞서 머지한 PR 본문의 서술 톤·상세도를 참고해 맞춘다.

## PR 본문 작성

작업 컨텍스트로 `/plan/pr{N}/` 하위의 모든 산출물과 커밋 로그를 전달한다. 특정 파일명을 하드코딩하지 않고 `/plan/pr{N}/`을 동적으로 탐색하여 존재하는 산출물을 참조한다. 4절을 아래 소스에서 합성한다. 정리된 본문은 필요 시 `/plan/pr{N}/consumable/pr-body.md`에 임시 정리한 뒤 PR에 반영한다.

### `[Jira 링크]`

브랜치명에서 티켓 키(`PLFT-XXXX`)를 추출한다.

- Jira base URL을 아는 경우: `[PLFT-XXXX](<base>/browse/PLFT-XXXX)` 형태로 링크한다.
- base URL(도메인)을 모르는 경우: 템플릿의 `(링크추가해주세요)` placeholder를 유지하고 추출한 티켓 키만 표기한 뒤, 사용자에게 링크 보완을 요청한다.
- 브랜치에 티켓 키가 없으면(신규 기능 등): placeholder를 유지하고 Jira 이슈 유무를 사용자에게 확인한다.

### `### 작업 배경`

overview.md의 의도(무엇을·왜)와 decisions.md의 핵심 결정을 녹인다.

### `### 변경 사항`

커밋 로그 기반 변경 요약 + Test plan 요약을 담는다.

- Test plan은 user-test-cases.md 시나리오를 녹인다. 동작 테스트 자동 판정 리포트가 있으면 결과 요약을 함께 첨부한다.
- 테스트·실행 명령은 [conventions/commands.md](../conventions/commands.md)를 단일 출처로 참조한다.

### `### 집중적으로 봐줬으면 하는 것`

리뷰어의 지적을 선제 대응하는 절이다. 다음을 녹인다.

- **리뷰 체크리스트 자가 점검 결과**: 구현·리뷰 단계에서 수행한 자가 점검을, 자주 지적되는 축(레이어 경계·공통 컴포넌트 재사용·네비게이션·DI 등)별로 스스로 통과했음을 근거와 함께 명시한다.
- **리뷰 초점**: 판단이 갈렸던 지점, 트레이드오프를 안고 택한 결정 등 리뷰어가 집중해서 봐야 할 부분.
- **Known issues / Follow-up**: overview.md의 「열려있는 질문」에서 이번 PR 범위 밖으로 남긴 항목.

작성 후 사용자가 톤·구조·분량을 다듬는다.

## 산출물 정리

PR 본문 작성이 완료되면, `/plan/pr{N}/` 하위의 각 산출물을 PR 본문 및 코드와 대조한다.

- 모든 내용이 PR 본문 또는 코드에 반영된 경우: 해당 파일 삭제. PR 본문 작업 파일 `pr-body.md`도 반영 완료분이므로 함께 폐기한다.
- 아직 반영되지 않은 판단·결정 내용이 남아 있는 경우: 해당 파일 유지.
- **`/plan/pr{N}/persistent/` 하위는 정리 대상에서 제외** — 영구 보존 자료. 대조도 수행하지 않는다.

대조는 수행하되, 사용자에게는 삭제·유지 파일 목록(유지 시 한 줄 사유)만 보고한 뒤 삭제한다.

## 2회차 최종 커밋 정리 (마지막 PR 한정)

본 PR이 **마지막 PR**(`/plan/` 하위 가장 높은 번호의 `pr{N}` 디렉토리가 현재 작업 중인 PR)이면, 머지 직전에 전체 PR 커밋 메시지의 `[PR{N}]` 접두사를 제거하고 메시지를 재작성한다. 마지막이 아니면 건너뛴다.

절차:

- 시작 전 백업 브랜치 필수: `git branch backup/<현재브랜치>-<YYYYMMDD-HHmm>`. history rewriting + force-push가 동반되므로, 사고 시 `git reset --hard backup/...`로 복구한다.
- `[PR{N}]` 접두사 제거·메시지 재작성. 리뷰 수정 커밋의 슬라이스별 정리는 step-4에서 완료됐으므로, 본 단계는 메시지 정리에 집중한다.
- 재작성 완료 후 force-push 요청 안내 (백업 브랜치 이름 + `git log` 결과 보고). force-push는 판단 게이트이며 실행은 사용자가 한다 (SKILL.md 「게이트 분류」).

## 종료 — 분기점

PR 본문·산출물 정리가 끝나면 WRITING 세션을 종료하고 PR 머지를 안내한다. 멀티 PR이면 머지 후 다음 PLAN(N+1) 진입을 안내한다 (SKILL.md 「세션 spawn 안내」). 멀티 PR은 순차로 진행하며, 다음 PR 설계를 현재 PR과 병행하지 않는다.
